# Apple Ads

> Manage Apple Ads API resources from asc

The existing resource commands under `ads` talk to the Apple Ads Campaign
Management API v5. Apple Ads Platform API v1 resources live under
`ads platform`; raw v1 requests remain available under
`ads platform api request`. Both use Apple Ads OAuth credentials, not App Store
Connect API keys.

Use `--help` before scripting a new command. Apple Ads has many nested
resources, and the CLI exposes the documented path parameters as flags:

```bash  theme={null}
asc ads --help
asc ads campaigns --help
asc ads campaigns create --help
```

For operator workflows, see [Apple Ads Operator Playbooks](/guides/apple-ads-playbooks).

## Credential Model

Apple Ads credentials are separate from App Store Connect credentials.
`asc auth login` does not configure `asc ads`.

For automation, configure an Ads profile with `asc ads auth login` or provide
Ads credentials through `ASC_ADS_*` variables. `ASC_ADS_ACCESS_TOKEN` skips
token exchange. Scoped v5 calls still need an organization ID; scoped v1 calls
need a separate ad account ID.

## Authenticate

Create an Apple Ads API key in Apple Ads, then store it with `asc ads auth`.
Apple Ads expects an EC P-256 private key. Keep the private key out of your
repo.

```bash  theme={null}
openssl ecparam -genkey -name prime256v1 -noout -out ./apple-ads-private-key.pem
openssl ec -in ./apple-ads-private-key.pem -pubout -out ./apple-ads-public-key.pem
```

Upload the public key in Apple Ads. Apple returns a `client_id`, `team_id`, and
`key_id` for that integration.

```bash  theme={null}
asc ads auth login \
  --name "Marketing" \
  --client-id "SEARCHADS_CLIENT_ID" \
  --team-id "SEARCHADS_TEAM_ID" \
  --key-id "KEY_ID" \
  --private-key ./apple-ads-private-key.pem \
  --org "123456" \
  --ad-account "987654"
```

Add `--network` during login when you want `asc` to request a token and call
`GET /v1/me` before storing the profile:

```bash  theme={null}
asc ads auth login \
  --name "Marketing" \
  --client-id "SEARCHADS_CLIENT_ID" \
  --team-id "SEARCHADS_TEAM_ID" \
  --key-id "KEY_ID" \
  --private-key ./apple-ads-private-key.pem \
  --org "123456" \
  --network
```

Validate and inspect stored credentials:

```bash  theme={null}
asc ads auth status --validate
asc ads auth discover --output json
asc ads auth doctor
```

Print a short-lived OAuth access token only when you explicitly confirm:

```bash  theme={null}
asc ads auth token --confirm --output json
```

For CI or agent runs, use environment variables instead of storing a profile:

```bash  theme={null}
export ASC_ADS_CLIENT_ID="SEARCHADS_CLIENT_ID"
export ASC_ADS_TEAM_ID="SEARCHADS_TEAM_ID"
export ASC_ADS_KEY_ID="KEY_ID"
export ASC_ADS_PRIVATE_KEY_PATH="$HOME/.asc/apple-ads-private-key.pem"
export ASC_ADS_ORG_ID="123456"
export ASC_ADS_AD_ACCOUNT_ID="987654"

asc ads campaigns --output json
```

`ASC_ADS_PRIVATE_KEY` and `ASC_ADS_PRIVATE_KEY_B64` also work when a CI system
can store the key material as a secret value. Use `ASC_ADS_BYPASS_KEYCHAIN=1`
when you want environment/config auth only.

If another system already minted a short-lived token, pass it directly:

```bash  theme={null}
export ASC_ADS_ACCESS_TOKEN="ACCESS_TOKEN"
export ASC_ADS_ORG_ID="123456"

asc ads campaigns --limit 10 --output json
```

## Organization context

Most Apple Ads endpoints require an organization context. Provide it with
`--org`, store it during login with `--org`, or set `ASC_ADS_ORG_ID`. If you do
not know the org ID yet, discover the active Ads user and available accounts:

```bash  theme={null}
asc ads auth discover --output json
```

Then pass an `accounts[].org_id` returned by Apple:

```bash  theme={null}
asc ads campaigns list --org "123456" --output json
```

These endpoints do not send the `X-AP-Context` organization header because
Apple defines them outside an org context:

```bash  theme={null}
asc ads me view
asc ads acls list
```

## Platform API ad account context

Apple Ads Platform API v1 uses an ad account ID in
`X-AP-Context: adAccountId=<id>;`. This is not the legacy organization ID, and
the CLI never substitutes one for the other. Provide the v1 value with
`--ad-account`, store it during login with `--ad-account`, or set
`ASC_ADS_AD_ACCOUNT_ID`.

The raw v1 command omits context for endpoints Apple documents as unscoped,
including `GET /v1/me`, `GET /v1/acls`, `GET /v1/orgs/{id}`,
`GET /v1/advertiser-resources`, and `POST /v1/ad-accounts`. Passing
`--ad-account` explicitly to one of those endpoints is rejected instead of
silently ignored.

Authentication discovery and validation also use the v1 `me` and `acls`
endpoints, so these public auth commands do not depend on the retiring v5 API:

```bash  theme={null}
asc ads auth status --validate
asc ads auth discover --output json
```

## Platform account and app commands

View identity and account access without an ad account context:

```bash  theme={null}
asc ads platform me view --output json
asc ads platform acls list --output json
asc ads platform orgs view --org-id "123456" --output json
asc ads platform advertiser-resources list --resource-type CONTENT_PROVIDER
```

Create an ad account with an `AdAccountCreate` JSON object. Viewing and updating
an ad account use the same `--ad-account` value for both the URL ID and the
`X-AP-Context` header:

```bash  theme={null}
asc ads platform ad-accounts create --file ad-account-create.json
asc ads platform ad-accounts view --ad-account "987654"
asc ads platform ad-accounts update --ad-account "987654" --file ad-account-update.json
```

`productFeatures` is immutable and rejected by `ad-accounts update`. Because
`delegations` replaces the complete delegation list, updates containing that
field also require `--confirm`; name-only updates do not.

Search apps by text, content-provider IDs, owned apps, or a combination. Store
fronts are passed as comma-separated ISO alpha-2 codes and sent as repeated v1
query parameters:

```bash  theme={null}
asc ads platform apps search --ad-account "987654" --query "Example" --store-fronts "US,GB" --paginate
asc ads platform apps view --ad-account "987654" --adam-id "123456789"
asc ads platform apps supported-languages find --ad-account "987654" --file query.json
asc ads platform apps eligibility find --ad-account "987654" --file query.json
asc ads platform rejection-reasons apps find --ad-account "987654" --file query.json
asc ads platform rejection-reasons apps view --ad-account "987654" --reason "42"
```

The three `find` commands above accept an omitted `--file` and then send no
request body. Use a `QueryRequest` or eligibility query file when filters,
sorting, or pagination are needed.

## Platform brands, locations, creatives, and assets

Brand and Apple Maps discovery uses ad-account context. Query operations accept
Apple's JSON query types through `--file`; the asset, creative, and brand
rejection-reason queries may omit the file when no selector is needed.

```bash  theme={null}
asc ads platform brands find --ad-account "987654" --file query.json
asc ads platform brands view --ad-account "987654" --brand "BRAND_ID"
asc ads platform business-categories find --ad-account "987654" --file query.json
asc ads platform business-categories view --ad-account "987654" --category "CATEGORY_ID"
asc ads platform locations find --ad-account "987654" --file query.json
asc ads platform locations view --ad-account "987654" --location "LOCATION_ID"
asc ads platform rejection-reasons brands find --ad-account "987654"
```

Location-group and creative create/update commands require JSON files. Their
delete commands, and asset deletion, require explicit confirmation before the
CLI reads credentials or sends a request.

```bash  theme={null}
asc ads platform location-groups create --ad-account "987654" --file location-group.json
asc ads platform location-groups update --ad-account "987654" --location-group "GROUP_ID" --file update.json
asc ads platform location-groups delete --ad-account "987654" --location-group "GROUP_ID" --confirm
asc ads platform creatives create --ad-account "987654" --file creative.json
asc ads platform creatives update --ad-account "987654" --creative "CREATIVE_ID" --file update.json
asc ads platform creatives delete --ad-account "987654" --creative "CREATIVE_ID" --confirm
```

Upload a PNG, JPEG, or HEIC asset with the dedicated multipart command. The CLI
uses the basename in the multipart filename and sends the selected brand as a
`BUSINESS_BRAND` promoted object. Apple processes the asset asynchronously;
poll `assets view` until `eligibility.status` is ready before using the asset in
a creative.

```bash  theme={null}
asc ads platform assets find --ad-account "987654"
asc ads platform assets upload --file ./brand.jpeg --brand "BRAND_ID" --ad-account "987654"
asc ads platform assets view --asset "ASSET_UUID" --ad-account "987654"
asc ads platform assets delete --asset "ASSET_UUID" --ad-account "987654" --confirm
```

## Platform campaign resources

Platform v1 campaign resources use string identifiers and an ad account
context. Create, update, and bulk commands require a JSON object file. The
read-only `find` commands accept an optional `QueryRequest` file; omit it to
send no request body.

```bash  theme={null}
asc ads platform campaigns create --ad-account "987654" --file campaign.json
asc ads platform campaigns find --ad-account "987654" --file query.json
asc ads platform ad-groups view --ad-account "987654" --ad-group "adgroup-id"
asc ads platform ads update --ad-account "987654" --ad "ad-id" --file ad.json
asc ads platform targeting-keywords create-bulk --ad-account "987654" --file keywords.json
asc ads platform negative-keywords find --ad-account "987654"
```

Delete commands require `--confirm`. Platform v1 has no bulk-delete operation:

```bash  theme={null}
asc ads platform campaigns delete --ad-account "987654" --campaign "campaign-id" --confirm
asc ads platform targeting-keywords delete --ad-account "987654" --keyword "keyword-id" --confirm
```

Pause and resume use the v1 campaign update endpoint with direct
`{"status":"PAUSED"}` or `{"status":"ENABLED"}` payloads and require
confirmation:

```bash  theme={null}
asc ads platform campaigns pause --ad-account "987654" --campaign "campaign-id" --confirm
asc ads platform campaigns resume --ad-account "987654" --campaign "campaign-id" --confirm
```

Search or resolve geographic targets, and query product-page locale data:

```bash  theme={null}
asc ads platform geo search --ad-account "987654" --supply-source APPSTORE --query "San Francisco" --entity Locality
asc ads platform geo resolve --ad-account "987654" --file geo.json
asc ads platform apps locales find --ad-account "987654" --adam-id "123456789"
asc ads platform product-pages locales find --ad-account "987654" --file query.json
```

Shared budgets retain the `budget-orders` command name. Create, update, and
delete are context-free; view and find accept an optional `--ad-account`.

```bash  theme={null}
asc ads platform budget-orders create --file shared-budget.json
asc ads platform budget-orders find --ad-account "987654"
asc ads platform budget-orders view --budget-order "budget-id"
asc ads platform budget-orders delete --budget-order "budget-id" --confirm
```

## Campaigns

List campaigns. The short form aliases `list`:

```bash  theme={null}
asc ads campaigns --org "123456" --limit 100 --output table
asc ads campaigns list --org "123456" --paginate --output json
```

Create or update resources with JSON payload files. The CLI sends the file body
to Apple without inventing extra field mappings. Apple requires campaign update
payloads to use a `campaign` envelope, so `campaign-update.json` must contain a
wrapped object such as:

```json  theme={null}
{
  "campaign": {
    "status": "PAUSED"
  }
}
```

```bash  theme={null}
asc ads campaigns create --org "123456" --file campaign.json
asc ads campaigns update --org "123456" --campaign 987654321 --file campaign-update.json
```

Delete commands always require `--confirm`:

```bash  theme={null}
asc ads campaigns delete --org "123456" --campaign 987654321 --confirm
```

## Ad Groups and Ads

Ad groups sit under campaigns. The nested `ads` command group is the Apple Ads
ad resource, so ad-resource commands read as `asc ads ads ...`:

```bash  theme={null}
asc ads ad-groups list --org "123456" --campaign 987654321 --output json
asc ads ad-groups create --org "123456" --campaign 987654321 --file ad-group.json
asc ads ads list --org "123456" --campaign 987654321 --ad-group 123456789 --output json
asc ads ads create --org "123456" --campaign 987654321 --ad-group 123456789 --file ad.json
```

Find endpoints use Apple selector payloads:

```bash  theme={null}
asc ads campaigns find --org "123456" --file selector.json --output json
asc ads ad-groups find --org "123456" --campaign 987654321 --file selector.json
asc ads ads find-org --org "123456" --file selector.json
```

```json selector.json
{
  "conditions": [
    {
      "field": "deleted",
      "operator": "EQUALS",
      "values": ["false"]
    }
  ],
  "pagination": {
    "offset": 0,
    "limit": 100
  },
  "orderBy": [
    {
      "field": "id",
      "sortOrder": "DESCENDING"
    }
  ]
}
```

## Payloads

Apple Ads request bodies are passed through as JSON. Object endpoints require a
JSON object. Bulk endpoints that accept arrays require a JSON array.

```json campaign.json
{
  "name": "Brand Campaign",
  "budgetAmount": {
    "amount": "1000",
    "currency": "USD"
  },
  "adamId": 1234567890,
  "countriesOrRegions": ["US"],
  "billingEvent": "TAPS",
  "dailyBudgetAmount": {
    "amount": "100",
    "currency": "USD"
  },
  "displayStatus": "PAUSED"
}
```

For live test data, prefer paused campaigns with a future start date and delete
them after verification. Do not use production campaigns for command-shape
testing.

```bash  theme={null}
asc ads targeting-keywords create-bulk \
  --org "123456" \
  --campaign 987654321 \
  --ad-group 123456789 \
  --file keywords.json
```

```json keywords.json
[
  {
    "text": "example keyword",
    "matchType": "EXACT",
    "bidAmount": {
      "amount": "1.00",
      "currency": "USD"
    },
    "status": "PAUSED"
  }
]
```

Bulk delete endpoints accept arrays of IDs:

```bash  theme={null}
asc ads targeting-keywords delete-bulk \
  --org "123456" \
  --campaign 987654321 \
  --ad-group 123456789 \
  --file keyword-ids.json \
  --confirm
```

```json keyword-ids.json
[111111111, 222222222]
```

## Keywords and Negative Keywords

Targeting keywords belong to an ad group:

```bash  theme={null}
asc ads targeting-keywords list --org "123456" --campaign 987654321 --ad-group 123456789
asc ads targeting-keywords create-bulk --org "123456" --campaign 987654321 --ad-group 123456789 --file keywords.json
asc ads targeting-keywords delete --org "123456" --campaign 987654321 --ad-group 123456789 --keyword 111111111 --confirm
```

Campaign negative keywords belong to a campaign. Ad group negative keywords add
`--ad-group`:

```bash  theme={null}
asc ads campaign-negative-keywords create-bulk --org "123456" --campaign 987654321 --file negative-keywords.json
asc ads ad-group-negative-keywords create-bulk --org "123456" --campaign 987654321 --ad-group 123456789 --file negative-keywords.json
```

```json negative-keywords.json
[
  {
    "text": "free",
    "matchType": "BROAD",
    "status": "ACTIVE"
  }
]
```

## Apps, Product Pages, Geo, and Creatives

These commands help you discover valid IDs before creating campaigns or ads:

```bash  theme={null}
asc ads apps search --org "123456" --query "My App" --limit 10 --output json
asc ads apps view --org "123456" --adam-id 1234567890 --output json
asc ads product-pages list --org "123456" --adam-id 1234567890 --states VISIBLE
asc ads product-pages locales list --org "123456" --adam-id 1234567890 --product-page "DEFAULT_PRODUCT_PAGE"
asc ads geo search --org "123456" --query "San Francisco" --country-code US --limit 10
asc ads creatives list --org "123456" --limit 100
asc ads rejection-reasons find --org "123456" --file selector.json
```

Apple does not allow every ad or creative to be deleted directly. For example,
Apple can reject direct deletes for default product page creative ads. In test
runs, clean those up by deleting the parent ad group or campaign when Apple
allows it.

## Reporting

Reporting endpoints accept Apple Ads `ReportingRequest` payloads:

```bash  theme={null}
asc ads reports campaigns --org "123456" --file reporting-request.json --output json
asc ads reports keywords --org "123456" --campaign 987654321 --file reporting-request.json
```

```json reporting-request.json
{
  "startTime": "2026-05-01",
  "endTime": "2026-05-31",
  "returnRowTotals": true,
  "returnGrandTotals": true,
  "selector": {
    "orderBy": [
      {
        "field": "impressions",
        "sortOrder": "DESCENDING"
      }
    ],
    "pagination": {
      "offset": 0,
      "limit": 100
    }
  }
}
```

`--paginate` is only exposed on documented query-parameter pagination endpoints.
Reporting and selector-body endpoints keep pagination inside the request body
exactly as supplied in `--file`.

## Impression Share Reports

```bash  theme={null}
asc ads impression-share-reports --org "123456" --limit 50 --output json
asc ads impression-share-reports create --org "123456" --file custom-report-request.json
asc ads impression-share-reports view --org "123456" --report 123456789
```

Apple Ads limits impression share report list pages to 50 rows.

## Endpoint Groups

`asc ads` includes commands for:

* auth, access control, and user details
* apps, app assets, product pages, locales, countries, and devices
* budget orders, campaigns, ad groups, and ads
* targeting keywords, campaign negative keywords, and ad group negative keywords
* geo search and geo resolution
* creatives and rejection reasons
* campaign, ad group, keyword, search term, ad, and ad-group scoped reports
* impression share reports

Every generated endpoint command supports `--ads-profile`. Every org-scoped
endpoint also supports `--org`. List-style endpoints that expose Apple
`limit`/`offset` query parameters also support `--paginate`.

## Raw API Requests

Use `ads api request` when Apple adds a new field before the first-class command
surface is updated, or when you need to debug an API response:

```bash  theme={null}
asc ads api request \
  --method POST \
  --path v5/campaigns/find \
  --org "123456" \
  --file selector.json \
  --output json
```

The raw request command only accepts Apple Ads v5 paths or
`https://api.searchads.apple.com/api/v5/...` URLs. `DELETE` requests require
`--confirm`.

Use the separate Platform API command for v1 paths:

```bash  theme={null}
asc ads platform api request \
  --method POST \
  --path v1/campaigns/query \
  --ad-account "987654" \
  --file query.json \
  --output json
```

It accepts only `v1/...` paths or `https://api.ads.apple.com/v1/...` URLs.
`GET` requests may retry transient v1 failures; mutation requests are never
replayed automatically. Empty successful v1 responses print `{}`.

## Agent Checklist

When you automate Apple Ads with a coding agent:

1. Run `asc ads <group> --help` before choosing flags.
2. Resolve the user and org with `asc ads auth discover --output json` unless `ASC_ADS_ORG_ID` is already known.
3. Use `--output json` for machine parsing.
4. Put request bodies in checked-in templates or temporary JSON files, not shell-escaped inline JSON.
5. Pass `--confirm` only after you have printed the target ID and cleanup plan.
6. For live mutation tests, create paused, clearly named resources and delete the parent campaign at the end.
